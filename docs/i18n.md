# Internacionalización (i18n)

Equigest usa [`next-intl`](https://next-intl.dev) en modo **App Router sin routing por
segmento de URL**. El idioma se resuelve por **cookie**, no por prefijo `/[locale]/`.

## Cómo está montado

| Pieza | Fichero | Qué hace |
| --- | --- | --- |
| Plugin | `next.config.ts` | `createNextIntlPlugin("./src/i18n/request.ts")` |
| Config compartida | `src/i18n/config.ts` | `LOCALES` (`es`, `en`), `DEFAULT_LOCALE` (`es`), `LOCALE_COOKIE` (`NEXT_LOCALE`), `isLocale()`. Sin imports de Next para poder usarse en cualquier lado. |
| Request config | `src/i18n/request.ts` | Lee la cookie `NEXT_LOCALE` con `cookies()` de `next/headers`, valida contra `LOCALES`, cae a `es`, y carga `messages/${locale}.json`. |
| Server action | `src/i18n/actions.ts` | `setLocale(next)` — escribe la cookie `NEXT_LOCALE` (`path=/`, 1 año, `sameSite=lax`). |
| Provider | `src/app/layout.tsx` | Único `NextIntlClientProvider` de la app, en el layout raíz, con `locale` de `getLocale()` y `messages` de `getMessages()`. También pone `<html lang={locale}>` dinámico y `generateMetadata()` traducido (`metadata.home`). |
| Selector de idioma | `src/components/i18n/locale-switcher.tsx` | Client component ES / EN. Llama a `setLocale()` y luego `router.refresh()`. Está en la nav de marketing (desktop + menú móvil), la pantalla de login y el pie del sidebar de la app. |

No hay más providers: como el único layout que renderiza `<html>` es el raíz,
un solo `NextIntlClientProvider` cubre `(marketing)`, `(auth)` y `(app)`.

## Ficheros de mensajes

- `messages/es.json` y `messages/en.json`.
- **Deben tener exactamente el mismo conjunto de claves.** Comprobación rápida:

  ```bash
  node -e "const a=require('./messages/es.json'),b=require('./messages/en.json');const k=o=>Object.keys(o).flatMap(x=>o[x]&&typeof o[x]==='object'&&!Array.isArray(o[x])?k(o[x]).map(y=>x+'.'+y):[x]);const A=k(a),B=k(b);console.log('solo es:',A.filter(x=>!B.includes(x)));console.log('solo en:',B.filter(x=>!A.includes(x)));"
  ```

### Convención de namespaces

| Namespace | Contenido |
| --- | --- |
| `app` | Nombre y descripción de la marca |
| `metadata` | Títulos/descripciones por ruta (`home`, `contact`, `privacy`, `terms`, `cookies`, `login`, `verify`, `authError`, `onboarding`, `demo`, `founders`) |
| `common` | Cadenas transversales: `back`, `localeSwitcher.*` |
| `marketing` | Landing: `nav`, `actions`, `hero`, `features`, `about`, `faq`, `pricing` |
| `demo` | Página `/demo`: recorrido por los módulos y la franja de rendimiento |
| `founders` | Página `/fundadores`: historia, diferencial y valores |
| `footer` | Enlaces del pie |
| `legal` | Páginas legales: `common` (fecha), `contact`, `privacy`, `terms`, `cookies` |
| `auth` | `login`, `verify`, `error` |
| `onboarding` | Formulario de alta de finca + `errors` (cliente) y `serverErrors` (server action) |
| `cookieBanner` | Banner de cookies |
| `sidebar` | Chrome de navegación de la app: `groups`, `sections`, `logout`, etc. |
| `nav` | Etiquetas cortas de secciones (stub heredado; el sidebar usa `sidebar.sections`) |

Reglas:

- Namespaces en `camelCase`; una sección de UI = un namespace o sub-objeto.
- Listas → arrays (`marketing.faq.items`, `legal.privacy.s1.items`); se leen con `t.raw(...)`.
- Texto con `<strong>` → se resuelve con `t.rich("clave", { strong: (c) => <strong>{c}</strong> })`.
- Interpolación con `{param}` (p. ej. `legal.common.lastUpdated`).

## Migrar una pantalla interna (aún en español a pelo)

Las pantallas internas (`caballos`, `sanidad`, `reproduccion`, `facturacion`,
`rendimiento`, `pupilaje`, `movimientos`, `tareas`, `documentos`, `ajustes`,
kiosko, escáner) **todavía no están traducidas**. Para migrar una:

1. Elige/crea un namespace en `messages/es.json` **y** `messages/en.json` con las
   mismas claves (p. ej. `horses`).
2. En cada componente:
   - **RSC / server component / server action:** `const t = await getTranslations("horses")` de `next-intl/server`.
   - **Client component (`"use client"`):** `const t = useTranslations("horses")` de `next-intl`.
3. Sustituye cada cadena literal por `t("clave")`. Para metadatos de ruta usa
   `generateMetadata()` con `getTranslations("metadata.*")`.
4. Verifica la paridad de claves con el snippet de arriba y ejecuta
   `npx tsc --noEmit` y `npm run build`.

## Pendiente

- **Fechas:** `date-fns` sigue con locale `es` fijo. Cuando se quiera localizar,
  seleccionar el locale de `date-fns` según `getLocale()`.
- `src/components/layout/page-header.tsx` tiene el texto por defecto `"Atrás"`;
  solo aparece en pantallas internas, así que se traducirá con ellas (haría falta
  volver el componente `async` o pasar `backLabel` ya traducido).
- No existe `Tenant.locale`: en esta fase el idioma es por cookie, sin campo ni
  migración en base de datos.
